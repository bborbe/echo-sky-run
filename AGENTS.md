# AGENTS.md

Instructions for coding agents working on Echo Sky Run. Read `VISION.md` first when it exists; until
then the game description is the source of truth.

## What this is

A 2D side-scrolling platformer in the spirit of *Super Mario World* with one twist: the player leaves a
**Ghost Echo**, a translucent copy of themselves that stays solid for 4 s. It is a browser game —
Vite + TypeScript, no framework, no game engine.

## Commands

Use the Makefile targets; each installs dependencies first when `node_modules` is missing or stale.

| Command | Wraps | What it does |
|---|---|---|
| `make run` | `npm run dev` | Start the Vite dev server |
| `make test` | `npm test` | Run the fast test tier (vitest project `fast`) — must be green before every commit |
| `make test-all` | `npm run test:all` | Run both tiers, fast + slow — run it before merging any physics change |
| `make build` | `npm run build` | Typecheck (`tsc`) and production build |
| `make e2e` | `npm run build` + `npm run e2e` | Build, serve it, and play level 1-1 in a muted headless browser. Also measures the p99 frame time and the input-to-frame latency, and checks the debug spawn URL. Needs the browser binary once: `npx playwright install chromium` |
| `make shots` | `npm run build` + `npm run shots` | Build, serve it, and write `shots/1-1-960x540.png` and `shots/1-1-1920x1080.png` from the debug spawn URL (`shots/` is gitignored) |

**Debug spawn URL:** `?level=1-1&x=<px>&y=<px>` starts Pip at that spot (pixel coordinates, not
tiles). Add `&freeze=1` to hold the simulation on the frame the page loaded — it renders one still
frame without the PAUSED banner, which is what makes a screenshot reproducible. The debug overlay's
P copies the current spot as that URL.

## Layout

| Path | Role |
|---|---|
| `src/physics/` | Fixed-timestep simulation: the 60 Hz accumulator loop, player movement and tile collision. Pure TypeScript. |
| `src/echo/` | Ghost Echo rules: mid-air placement, the air charge, the 240 f lifetime, the one-way top, the wall refusal. Pure and tested. |
| `src/render/` | Canvas renderer filling the browser window: a fixed 224 px logical height, a logical width derived from the window's aspect, and a fractional nearest-neighbour scale. The only place that touches the DOM or a canvas context. |
| `src/render/camera.ts` | The camera as a pure value — scroll offset and deadzone, with no velocity term. DOM-free, so the framing is a unit test. |
| `src/levels/` | Level tile strings, one character per tile, plus the level's own playthrough tests. |
| `src/game/sim.ts` | The whole-game fixed step: places the Echo, steps the player, ages the Echoes, refreshes the air charge and checks the goal. Deterministic — the level's test and the browser check both drive it. |
| `scripts/` | `e2e.mjs`, the browser playthrough check (`npm run e2e`, `make e2e`), and `shots.mjs`, the screenshot tool (`npm run shots`, `make shots`). |
| `src/levels/level1-1.replay.ts` | The golden replay fixture: a recorded 1-1 run, RLE-encoded. Generated by re-recording, never hand-edited. |
| `src/audio/` | Sound, all synthesised (no sample files). `synth.ts`, `recipes.ts` and `score.ts` are pure, so vitest renders and measures every sound. `events.ts` maps a fixed step to its sound events. `engine.ts` is the only Web Audio code; the bank renders in `render.worker.ts`. `?audiolog=1` traces every sound; `?vol=0` mutes. |
| `src/main.ts` | Browser shell: wires input → simulation → renderer, and owns the `requestAnimationFrame` loop. |
| `src/build-info.ts` | Build label (short SHA · build time · version), fed by `define` in `vite.config.ts` — the same value as `<meta name="commit">`. |

## Rules

- **Physics isolation:** nothing under `src/physics/` or `src/echo/` may import the DOM, a canvas, or
  any browser API. They stay pure and deterministic — no `Math.random`, `Date`, or `performance.now`.
  Time enters only as the fixed `DT`.
- **Determinism is tested:** the same input sequence over the same number of ticks must produce
  bit-identical state. Any physics change keeps that test green.
- **Rendering is decoupled:** the renderer draws interpolated state and never advances the simulation.
  A frame-rate change must not change what the simulation does.
- **Tuning values live in one place.** `RUN_MAX` 2.25 px/f, `SPRINT_MAX` 3.0 px/f at meter 112,
  `METER_MAX` 112, coyote time `COYOTE_F` 6 f, jump buffer `JUMP_BUFFER_F` 6 f, Echo life `ECHO_LIFE_F`
  240 f, one air charge `ECHO_AIR_CHARGES` 1. Never loosen a test to make a constant pass.
- **Tests drive the real path:** go through the simulation's own step function, never a hand-set flag
  the game does not produce.
- **Driven browsers are cheap:** every browser an agent drives launches with `--mute-audio` and a
  960×540 viewport, and the session is closed as soon as its shots are taken. Audio on the operator's
  speakers is a defect, not noise.

## Feel and performance budgets

These are the numbers from [[Exceptional Platformer Design Guide]] that this level must hold. Each is
a test, not a note — a regression fails `make test` or `make e2e` instead of surfacing at a play gate.

| Budget | Value | Where it is enforced |
|---|---|---|
| Input-to-frame | ≤ 3 frames | `src/physics/input-latency.test.ts` (fixed-step sampling, 30–165 Hz), and a real key press measured in `make e2e` |
| Corner correction | ≤ 4 px | `src/physics/corner.test.ts` — a rising jump that clips a ceiling corner slips past; a 6 px overlap still stops |
| Camera framing | No lead in the direction of travel — Pip stays within the dead zone of the view centre | `src/render/camera.test.ts`, over view widths 224–800 px at 1 px and 3 px steps |
| Frame time | p99 < 18 ms | `make e2e` — the live `requestAnimationFrame` loop's own p99 over a 120-frame window |
| Heap allocations | zero per frame in the fixed step | `src/game/alloc.test.ts` — asserts the per-frame scratch objects and arrays keep their identity |
| Golden replay | frame-exact | `src/levels/level1-1.replay.test.ts` — a recorded 1-1 run must land on the same frame, position and velocity |

**A budget is met by retuning a constant, never by loosening a test.** If the camera misses the
dead zone, change `CAMERA_DEADZONE_X`; if a jump clips a corner it should not, change
`CORNER_CORRECTION_PX`. Widening a threshold moves the bar the guide set.

**The allocation budget is enforced structurally, not by a heap measurement.** V8 optimises
short-lived objects away and scavenges the rest between two `memoryUsage()` samples, so an
allocating loop and an allocation-free one both measure ~0 bytes per iteration — a test built on
that number passes whatever the code does. What the code guarantees instead is object reuse, which
is observable: every scratch box and per-frame array keeps its identity across calls. A
re-introduced `map`/`filter`/object literal changes an identity and the test fails.

**The golden replay is a fixture, not a driver.** `src/levels/level1-1.replay.ts` holds the recorded
per-frame input of a run that clears the level. When a physics or level change is intended, re-record
it (the recorder is in the file's header comment) and review the fixture diff — a fixture updated
without a look is a test that no longer guards anything.

**Re-recording uses the enemy-free map**, the same one `level1-1.test.ts` uses: enemies and the ?
block change a scripted run's shape, and both have their own tests. The shipped level's playthrough
is the browser check's job.

## Workflow

Feature branch + pull request into `master`, merged with a merge commit (`gh pr merge --merge`).

- **Every PR adds a CHANGELOG bullet** under `## Unreleased` (`feat:` / `fix:` / `chore:` …), which
  drives the automatic release.
- **PRs merge on green CI:** `.github/workflows/ci.yml` runs `npm ci`, `npm test` (fast tier) and
  `npm run build` on every pull request. `pages.yml` deploys production on push to `master` and a
  playable preview per open PR at `https://bborbe.github.io/echo-sky-run/pr-<n>/`.
- **Verify a deploy by `<meta name="commit">`**, never by the Pages run's colour: a `cancelled` Pages
  run is a queued run replaced by a newer one, which deploys the live master head.

## Test tiers

Tests are split into two vitest projects in `vite.config.ts`: `slow` is an explicit `SLOW_TESTS` list,
`fast` is every other `src/**/*.test.ts`. A new test file is fast by default; if it takes ≥ 2 s in the
`ci.yml` log, add it to `SLOW_TESTS`.

| Tier | Runs | Where |
|---|---|---|
| fast | `npm test` / `make test` | every PR and master commit (`ci.yml`), before every commit locally |
| fast + slow | `npm run test:all` / `make test-all` | every `v*` tag (`release.yml`), locally before merging a physics change |
| slow | `npm run test:slow` | nightly on master (`nightly.yml`); red opens or comments a `nightly-failure` issue |

Releases are automatic (`.maintainer.yaml` `release.autoRelease`). Every PR adds a bullet under
`## Unreleased` in `CHANGELOG.md` — the releaser cuts a release only when that section is non-empty.
Never cut a release by hand.
