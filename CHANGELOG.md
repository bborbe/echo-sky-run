# Changelog

All notable changes to this project will be documented in this file.

Please choose versions by [Semantic Versioning](http://semver.org/).

* MAJOR version when you make incompatible API changes,
* MINOR version when you add functionality in a backwards-compatible manner, and
* PATCH version when you make backwards-compatible bug fixes.

- feat: a looping `?autopilot=1` run restarts itself after the results screen, so one page load clears the level over and over. The results screen holds for ~1.5 s first, so its time and best time stay readable; `resetGame()` then starts the next run through the same teardown a manual RETRY uses, and `show('level')` leaves the results screen. Looping is the default — `readLoop` sits beside the other URL readers and is on whenever `autopilot=1` is present — and `?loop=0` is the one-shot escape that leaves the run on its results screen, so `scripts/autopilot-check.mjs` keeps recording a single clear. - feat: any level plays itself from a URL. `?autopilot=1` hands each fixed step to a driver that turns the scripted decision into the same `SimInput` the keyboard produces, so the run goes through `advance()` exactly as a player's does — the frame loop never knows which one it is feeding, and nothing skips the simulation. The decision moved out of `runAutopilot` into `autopilotDecision(sim, echoAtX, echoUsed)`, which the toolkit run and the browser driver both call, so the two cannot drift; `echoUsed` is threaded through rather than held inside it, because the driver owns one per run and resets it on a restart. `src/autopilot-driver.ts` carries no level — the level arrives as the running sim, which is what lets one driver serve every level — and `readAutopilot` sits beside the other URL readers in `src/debug/overlay.ts`, off unless exactly `1`. `autopilot` joins the debug-entry list, so the URL starts in the level rather than on the title. The driver is proven on two fixtures — 1-1 plus a narrower synthetic level whose gap sits elsewhere and whose `echoAtX` differs — so a decision that hardcodes 1-1 geometry cannot pass, and a stub of the shared decision proves the driver's input comes from it rather than from a baked array.
- feat: the level toolkit every later level must pass, and 1-1 passing it. `src/toolkit/` holds four checks, all pure and DOM-free: an autopilot that clears the *populated* level (enemies, ? block, checkpoint) with 0 deaths and records every take-off with its landing; a no-Echo bypass sweep over launch position × speed × vertical launch (jump, sprint jump, and a stomp or shell bounce from three heights) × power tier, proving no launch state crosses an Echo beat without the Echo; and a blind-jump check measuring each landing against the view at take-off, at 960×540. The toolkit derives its own level grammar rather than reading constants — `findPits` walks the grid, `maxJumpReach` measures a sprint jump through the real `stepPlayer`, and a pit wider than that reach is an Echo beat, so a level with an Echo beat and no declared `echoAtX` is refused. `make test` now runs the fast tier **and** the browser playthrough (`make test-unit` is the fast tier alone), because those are the guide's two required checks; a red half fails the target. Every check ships with a known-positive control, so a clean report cannot come from a check that never fires. Applied to 1-1, the checks find one real blind landing — the jump off the Echo carries Pip 42 px past the view's right edge before he comes down, which the tutorial sign is what makes readable. `logicalViewWidth` moved beside `VIEW_H` so the check measures the view the renderer actually draws.

A read of broken or hostile storage still yields an empty save rather than a game that will not start, and the settings key is never touched.
